MÓDULO 01

Control de Versiones

Historial inteligente, colaboración sin conflictos y trazabilidad total del código fuente.

¿Qué es el control de versiones?

Es un sistema que registra y administra los cambios realizados sobre un archivo o conjunto de archivos a lo largo del tiempo, permitiendo recuperar versiones específicas más adelante. Cada punto guardado (commit) almacena quién hizo el cambio, cuándo ocurrió y qué líneas fueron modificadas.

¿Cómo funciona internamente?

En sistemas modernos como Git, el proyecto se gestiona mediante instantáneas (snapshots) identificadas por un hash criptográfico SHA-1. El flujo atraviesa tres estados: Working Directory (edición), Staging Area (preparación) y Repository (historial confirmado).

Tipos de sistemas (Cuáles son)

1. Locales (LVCS) — Ej. RCS

Mantienen una base de datos de parches en el disco duro local de una sola máquina. No están diseñados para trabajo colaborativo en red.

2. Centralizados (CVCS) — Ej. Subversion (SVN), Perforce

Existe un único servidor central que contiene todos los archivos versionados y varios clientes descargan copias desde ese nodo central.

3. Distribuidos (DVCS) — Ej. Git, Mercurial

Cada desarrollador clona el repositorio completo junto con todo su historial. Si el servidor cae, cualquier copia local puede restaurarlo.

Características, ventajas y desventajas

Tipo Características Ventajas Desventajas
Local (LVCS) Base de datos de cambios en un solo equipo. Rápido, simple y sin configuración de red. Imposible colaborar en equipo; pérdida total si falla el disco.
Centralizado (CVCS) Servidor único con control granular de permisos. Administración centralizada y fácil de entender. Punto único de fallo; requiere conexión constante al servidor.
Distribuido (DVCS) Historial completo en cada cliente y soporte de ramas ligeras. Trabajo offline, altísima velocidad, ramas y fusiones seguras. Curva de aprendizaje inicial mayor (ramas, rebase, conflictos).

Rastreo, gestión de cambios y ejemplos

  • Ramas (Branches): Permiten desarrollar una función (ej. feature/login-biometrico) sin afectar la rama estable main.
  • Comparación (Diff & Log): Con git log y git diff se audita exactamente qué línea cambió entre dos versiones.
  • Reversión segura: Si una actualización introduce un bug en producción, git revert deshace el commit sin borrar la historia.
  • Ejemplo práctico: Dos desarrolladores editan la pantalla de perfil; uno crea fix/avatar y otro feat/dark-mode. Mediante un Pull Request revisan los cambios y los integran ordenadamente.
Flujo práctico Git 
$ git init
$ git checkout -b feature/auth
$ git add .
$ git commit -m "feat: pantalla de login"
$ git push -u origin feature/auth
MÓDULO 02

Persistencia y Acceso a Datos

Cómo conservan, estructuran y sincronizan la información las aplicaciones móviles.

Definición y características

La persistencia de datos es la capacidad de una aplicación para almacenar información en un medio no volátil de manera que sobreviva al cierre de la app o al reinicio del dispositivo. Sus características clave son: durabilidad, integridad, rapidez de consulta, seguridad/cifrado y capacidad de sincronización.

Formas de persistencia y tipos de datos almacenables

📁

1. Archivos (Almacenamiento Interno/Externo)

Lectura y escritura directa en el sistema de archivos del dispositivo (sandboxing privado de la app o almacenamiento compartido).

Datos almacenables: Imágenes (JPG/WebP), audio (MP3/AAC), video (MP4), PDFs, logs y configuraciones JSON/XML.

🗄️

2. Bases de Datos Locales

Motores integrados dentro del teléfono (como SQLite o Realm) y almacenes clave-valor (SharedPreferences / DataStore).

Datos almacenables: Registros estructurados en tablas (usuarios, notas, carrito offline, historial, tokens y preferencias).

☁️

3. Bases Remotas mediante Servicios Web

La app se comunica por red con un servidor backend (API REST o GraphQL) conectado a motores en la nube (PostgreSQL, Firestore, MongoDB).

Datos almacenables: Datos multiusuario, catálogos en tiempo real, mensajes, transacciones y respaldos sincronizados.

Mecanismos de control de acceso

  • Bibliotecas de clases nativas: Clases como File, FileInputStream o DataStore encapsulan operaciones de entrada/salida (I/O) y permisos del sistema operativo.
  • Clases de SQLite: APIs como SQLiteOpenHelper y Cursor permiten crear esquemas, ejecutar consultas SQL manuales y recorrer filas.
  • Mapeo Relacional de Objetos (ORM): Herramientas como Room (Android) o Core Data / SwiftData (iOS) convierten tablas SQL en clases/objetos seguros, validando consultas en tiempo de compilación.

Autenticación y consumo de servicios web

1

Credenciales: La app envía usuario/contraseña o proveedor OAuth vía HTTPS (TLS).

2

Validación y Token: El servidor verifica y devuelve un token firmado (ej. JWT) + Refresh Token.

3

Almacenamiento seguro: El token se guarda en EncryptedSharedPreferences o Keychain.

4

Consumo REST: Clientes como Retrofit envían Authorization: Bearer <token> y deserializan el JSON.

Ejemplo real: Una app bancaria autentica con biometría + JWT, descarga los movimientos desde su API REST y los guarda en Room para consultarlos incluso en modo avión.

MÓDULO 03

Gestión de Sensores

Interacción física entre el dispositivo móvil y el entorno del usuario.

Definición de sensores

Los sensores móviles son componentes de hardware (y sensores virtuales derivados por software) integrados en el teléfono que miden magnitudes físicas —como aceleración, rotación, campos magnéticos, luz o posición— y las transforman en señales digitales interpretables por la aplicación.

Tipos de sensores en dispositivos móviles

Sensores de Movimiento

  • Acelerómetro: Mide la fuerza de aceleración en los ejes X, Y, Z (incluyendo gravedad). Uso: podómetros, detección de agitado.
  • Giroscopio: Mide la velocidad angular de rotación. Uso: videojuegos, estabilización de cámara y realidad aumentada.

Sensores de Posición

  • GPS / GNSS: Determina latitud, longitud y altitud mediante satélites. Uso: mapas, rutas y entregas.
  • Magnetómetro: Mide el campo magnético terrestre. Uso: brújula digital y orientación en mapas.
  • Proximidad: Detecta objetos cercanos al frontal (apaga la pantalla durante llamadas).

Sensores Ambientales

  • Fotómetro (Luz ambiental): Mide la iluminancia en lux para ajustar el brillo automático.
  • Barómetro: Mide presión atmosférica para mejorar precisión de altitud y clima.
  • Termómetro / Higrómetro: Monitorean temperatura y humedad ambiental/interna.

Proceso de gestión de sensores

01

Habilitación

Obtener el servicio (SensorManager), verificar si el sensor existe en el dispositivo y solicitar permisos en tiempo de ejecución (ej. ubicación).

02

Obtención

Registrar un listener (SensorEventListener) definiendo la frecuencia de muestreo (SENSOR_DELAY_UI, GAME, etc.).

03

Procesamiento

Aplicar filtros (paso bajo/alto) para eliminar ruido de hardware, calcular magnitudes y actualizar la interfaz de usuario.

04

Liberación

Cancelar el registro en onPause() o onStop() para evitar drenaje innecesario de batería.

MÓDULO 04

Uso de Recursos Multimedia

Integración de gráficos, sonido, video y movimiento para experiencias inmersivas.

Definición

Los recursos multimedia son todos los activos digitales visuales, auditivos e interactivos integrados en una aplicación móvil para comunicar información, guiar la navegación y enriquecer la experiencia del usuario (UX).

🖼️ Imágenes

Iconos vectoriales (SVG/VectorDrawable), fotografías y texturas optimizadas en formatos WebP, PNG y JPG.

🎵 Audio

Efectos de interfaz, notas de voz y streaming musical en MP3, AAC, OGG y WAV.

🎬 Video

Tutoriales, vistas previas y contenido en alta definición con códecs H.264 / H.265 (MP4, WebM).

✨ Animaciones

Transiciones de pantalla, vectores animados (Lottie) y físicas de movimiento fluido.

📊 Visuales dinámicos

Canvas 2D/3D, partículas, gráficas interactivas y shaders renderizados en tiempo real.

Estructura en el proyecto móvil
app/src/main/
├── assets/         # Archivos crudos (fuentes, JSON Lottie)
└── res/
    ├── drawable/   # Imágenes, formas XML y vectores
    ├── mipmap/     # Iconos del lanzador por densidad
    ├── raw/        # Audios y videos locales empaquetados
    └── anim/       # Definiciones XML de animaciones

Componentes de software multimedia

  • Renderizado de imágenes: ImageView, Image (Jetpack Compose) junto con librerías de caché como Coil o Glide.
  • Reproducción de audio y video: MediaPlayer para sonidos cortos y AndroidX Media3 (ExoPlayer) o AVPlayer (iOS) para streaming adaptativo.
  • Captura multimedia: APIs como CameraX y MediaRecorder para grabar foto, video y micrófono.
  • Motores de animación: AnimatedVisibility, LottieAnimationView y Canvas.
MÓDULO 05

Servicios, Notificaciones y Nube

Ejecución en segundo plano, intercambio de datos y conectividad cloud en tiempo real.

¿Qué son los Servicios?

Componentes de aplicación diseñados para ejecutar operaciones de larga duración o procesos remotos sin ofrecer una interfaz gráfica directa al usuario.

Tareas en Segundo Plano

Procesos que se ejecutan cuando la app está minimizada o cerrada (sincronización, descargas, copias de seguridad), gestionados hoy con WorkManager para respetar el ahorro de batería.

Tratamiento de Notificaciones

Alertas del sistema (locales o remotas vía Push) organizadas por canales de prioridad, con acciones rápidas, iconos y navegación profunda (Deep Links).

Proceso de implementación

  • Proveedores de Contenido (Content Providers): 1) Definir esquema URI, 2) Heredar de ContentProvider e implementar query/insert/update/delete, 3) Declarar en el Manifest con permisos de lectura/escritura.
  • Tareas en segundo plano: 1) Crear clase Worker, 2) Definir restricciones (Wi-Fi, batería), 3) Encolar con WorkManager.getInstance().enqueue().
  • Notificaciones: 1) Solicitar permiso POST_NOTIFICATIONS, 2) Registrar NotificationChannel, 3) Construir con NotificationCompat.Builder y emitir con NotificationManager.

Servicios de cómputo en la nube para móviles (BaaS / Cloud)

Firebase (Google): Authentication, Cloud Firestore, Realtime Database, Cloud Storage y Firebase Cloud Messaging (FCM) para notificaciones push.
AWS Amplify / Mobile: Cognito (identidad), AppSync (GraphQL), S3 (archivos) y SNS (mensajería push).
Supabase / Azure Mobile: Bases de datos PostgreSQL administradas, funciones serverless y sincronización offline-first.
MÓDULO 06

Librerías y Toolkits para Desarrollo Móvil

Acelera el desarrollo reutilizando módulos especializados y kits completos de interfaz y arquitectura.

¿Qué es una Librería?

Es una colección de clases, funciones y código precompilado enfocada en resolver una tarea específica. Tu aplicación mantiene el control del flujo y llama a la librería cuando la necesita (ej. hacer peticiones HTTP o cargar imágenes).

Librerías de funciones especializadas

  • Red y APIs: Retrofit, OkHttp, Ktor, Alamofire.
  • Imágenes: Coil, Glide, Picasso, Kingfisher.
  • Inyección de dependencias: Dagger Hilt, Koin.
  • Serialización JSON: Moshi, Gson, Kotlinx Serialization.

¿Qué es un Toolkit?

Es un conjunto integral de herramientas, SDKs, widgets de interfaz, compiladores y utilidades diseñados para construir toda una aplicación o ecosistema completo bajo una misma filosofía.

Diferenciación de Toolkits móviles

  • Android Jetpack / Compose (Nativo Android): Toolkit oficial de Google en Kotlin con UI declarativa y acceso directo a APIs del sistema.
  • SwiftUI (Nativo iOS): Toolkit declarativo de Apple para iOS, iPadOS y watchOS con rendimiento nativo máximo.
  • Flutter (Multiplataforma Google): Usa Dart y su propio motor gráfico (Impeller) para dibujar interfaces idénticas en Android e iOS.
  • React Native (Multiplataforma Meta): Usa JavaScript/TypeScript y puentea hacia componentes nativos de cada plataforma.
MÓDULO 07

Depuración y Seguridad

Detección precisa de fallos y blindaje de datos, comunicaciones y código binario.

¿Qué es la Depuración (Debugging)?

Es el proceso sistemático de identificar, aislar, analizar y corregir defectos (bugs) o cuellos de botella en el código fuente antes y después de publicar la aplicación.

Herramientas de depuración en el entorno móvil

  • Logcat / Consola: Visualiza registros en tiempo real filtrados por nivel (Verbose, Debug, Info, Warning, Error).
  • Breakpoints y Step-Over: Pausa la ejecución en una línea exacta para inspeccionar variables y la pila de llamadas (Call Stack).
  • Android Profiler / Xcode Instruments: Mide consumo de CPU, fugas de memoria (Memory Leaks), tráfico de red y energía.
  • Layout Inspector / App Inspection: Inspecciona la jerarquía visual 3D y consultas en vivo de bases de datos Room/SQLite.

¿Qué es la Seguridad Móvil?

Es el conjunto de controles arquitectónicos y buenas prácticas destinados a proteger la confidencialidad, integridad y disponibilidad de los datos del usuario y la lógica de la app frente a ataques.

Prácticas esenciales (OWASP Mobile)

  • Cifrado en tránsito: Uso obligatorio de HTTPS/TLS y Certificate Pinning contra ataques Man-in-the-Middle.
  • Cifrado en reposo: Uso de Android Keystore / iOS Keychain para llaves y tokens sensibles.
  • Ofuscación de código: Uso de R8 / ProGuard para dificultar la ingeniería inversa del APK/AAB.
  • Principio de mínimo privilegio: Solicitar únicamente los permisos estrictamente necesarios.
